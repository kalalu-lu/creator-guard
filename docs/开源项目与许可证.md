# 开源项目与许可证清单

> 本项目不是简单“套壳”，而是把下面这些项目的**可复用部分**拼起来：
> 浏览器扩展负责页面读写，FastAPI 负责本地编排，Ollama 负责模型运行时，Qwen 负责中文判断，SQLite 负责留存。
>
> 许可证以各项目仓库最新 `LICENSE` 为准。商用/分发前请逐个确认，尤其是模型许可证。

---

## 1. 实际运行依赖（必须）

### 1.1 Ollama

- 仓库：<https://github.com/ollama/ollama>
- 官网：<https://ollama.com/>
- 许可证：MIT
- 本项目用到的部分：
  - `POST /api/chat`：把 system/user prompt 发给本地模型，要求 `format: "json"`。
  - `GET /api/tags`：健康检查，确认模型是否已拉取。
  - `ollama pull`：模型下载。
- 修改方式：不需要改 Ollama 源码；所有调用封装在 `server/llm.py`。

### 1.2 Qwen2.5

- 仓库：<https://github.com/QwenLM/Qwen2.5>
- 模型页：<https://ollama.com/library/qwen2.5>
- 许可证：Qwen2.5 的 7B/14B 等尺寸通常为 Apache-2.0；不同尺寸/版本可能不同，以模型卡为准。
- 本项目默认：`qwen2.5:7b-instruct`
- 用到的部分：
  - 私信分类：`illegal / malicious / collab / suggestion / spam / normal`
  - 评论逐条分类：类别、立场、主题、是否可执行建议
  - 建议合并总结
- 修改方式：
  - 换模型：改 `.env` 的 `CG_OLLAMA_MODEL`。
  - 换判断标准：改 `server/prompts.py`。
  - 换调用协议：改 `server/llm.py`。

### 1.3 FastAPI

- 仓库：<https://github.com/fastapi/fastapi>
- 许可证：MIT
- 用到的部分：
  - 路由：`/api/dm/preview`、`/api/dm/classify`、`/api/comments/classify`、`/api/comments/stats` 等。
  - Pydantic 请求校验：限制文本长度、平台枚举、批量条数。
  - lifespan：启动时建库、清理过期数据、启动每小时的统计检查任务。
- 修改方式：`server/app.py`。

### 1.4 Uvicorn

- 仓库：<https://github.com/encode/uvicorn>
- 许可证：BSD-3-Clause
- 用到的部分：ASGI 服务器，`uvicorn server.app:app --host 127.0.0.1 --port 8765`。
- 注意：`requirements.txt` 用的是普通 `uvicorn`，不是 `uvicorn[standard]`，避免 Windows 上编译 PyYAML 失败。

### 1.5 SQLite

- 官网：<https://sqlite.org/>
- 许可证：Public Domain
- 用到的部分：Python 标准库 `sqlite3`，WAL 模式，本地单文件数据库。
- 表：
  - `dm_messages`：私信分类结果、原文哈希、缓存标注。
  - `comments`：评论逐条分类。
  - `thread_stats`：5 天统计快照。
  - `feedback`：人工纠错。
  - `audit_log`：启动/清理/导出等操作日志（不存正文）。

### 1.6 Chrome Manifest V3

- 文档：<https://developer.chrome.com/docs/extensions/mv3/>
- 用到的部分：
  - `content_scripts`：在 B 站/小红书页面读取 DOM、插入 badge/遮罩。
  - `service_worker`：统一代理本地 API 请求，避免 CORS。
  - `chrome.storage.local`：保存开关、每日计数。
  - Shadow DOM：隔离面板样式。
- 本项目用原生 MV3，没有引入 WXT/Plasmo 等框架，目的是**零构建、复制即用**。
- 如果你要工程化：
  - [WXT](https://github.com/wxt-dev/wxt)（MIT）：更好的开发体验、HMR、打包。
  - [Plasmo](https://github.com/PlasmoHQ/plasmo)（MIT）：React 扩展框架。
  - 但会把“复制粘贴就能跑”变成“要 npm install/build”，不适合本教程的零基础用户。

## 2. 可选增强（当前未默认启用）

### 2.1 BERTopic + sentence-transformers + bge-small-zh

- BERTopic：<https://github.com/MaartenGr/BERTopic>（MIT）
- sentence-transformers：<https://github.com/UKPLab/sentence-transformers>（Apache-2.0）
- bge-small-zh-v1.5：<https://huggingface.co/BAAI/bge-small-zh-v1.5>（MIT）

用途：

- 评论量 > 1000 时，单靠 LLM 逐条打 `topic` 标签成本高。
- 用 `bge-small-zh-v1.5` 把评论转成向量，BERTopic 聚类，得到“观众在聊什么”的主题。
- 再把每个 cluster 的摘要交给 Qwen，生成更细的“观点占比”。

怎么接：

1. 新建 `server/ml/topic.py`。
2. 在 `stats.py` 的 `compute_stats` 里，如果 `total > 1000`，用聚类结果替换 `stance_counts`。
3. 前端 `comments-core.js` 的 `makeBarRow` 不用改，仍然吃 `bars` 数组。

注意：

- 首次运行会下载模型（几百 MB）。
- CPU 也能跑，但比 LLM 逐条判断慢；适合离线批处理。
- 不要在处理请求的同步路径里跑，放到后台任务。

### 2.2 PaddleOCR

- 仓库：<https://github.com/PaddlePaddle/PaddleOCR>
- 许可证：Apache-2.0

用途：

- 极少数平台把文字画进 canvas，DOM 读不到。
- 对聊天区截图做 OCR，提取文字。

为什么默认不开：

- 截图可能包含头像、昵称、手机号，隐私风险更高。
- OCR 有错误率，会污染分类。
- 大多数场景 DOM 已经够用。

### 2.3 ShieldLM

- 仓库：<https://github.com/thu-coai/ShieldLM>
- 许可证：Apache-2.0（以仓库为准）

用途：

- 对高风险私信做第二模型复核，降低“违法/恶意”漏判。
- 适合把“宁可错杀”放在第一位的场景。

为什么默认不开：

- 多加载一个模型，内存翻倍。
- 7B 单模型 + 规则层已经能覆盖大部分明显案例。
- 两个模型意见不一致时，需要产品决策（谁优先）。

### 2.4 Playwright

- 仓库：<https://github.com/microsoft/playwright>
- 许可证：Apache-2.0

为什么**没有**用它：

- Playwright 需要另起浏览器/注入登录态，行为特征比扩展更明显。
- 需要保存 Cookie/Storage State，隐私风险更高。
- 更适合测试，不适合长期挂在创作者账号上。
- 本项目选择“扩展读取用户已登录页面”，风险相对低，但仍不是零。

### 2.5 APScheduler

- 仓库：<https://github.com/agronholm/apscheduler>
- 许可证：MIT

为什么没有用：

- 只需要“每小时检查一次有没有到期评论区”，`asyncio` 一个循环就够。
- 少一个依赖，少一个 Windows 兼容问题。

## 3. 本项目自己的代码

- 许可证：MIT（见根目录 `LICENSE`）。
- 你可以：
  - 修改 prompt、规则、选择器、UI。
  - 商用/分发（需保留 MIT 声明）。
  - 把服务端换成其他模型。
- 你不可以：
  - 用本项目做大规模骚扰、爬取他人隐私、绕过平台风控。
  - 把别人的私信/评论数据打包出售。
