# Creator Guard 保姆级安装教程（Windows）

> 目标：从一台干净的 Windows 电脑开始，装好 Python、Ollama、本地服务、浏览器扩展，然后在 B 站/小红书页面上看到私信标签和评论统计面板。
>
> 全程不需要写代码；需要改的地方我会告诉你“打开哪个文件、改哪一行、复制什么”。

---

## 0. 先看这一页：风险与边界

这个工具做的是：

- 读取你**已经登录的浏览器页面**上已经渲染出来的文字。
- 在页面上加标签、遮罩、统计面板。
- 可选：按较慢的节奏点击未读私信，读取全文。
- 不发送、不回复、不拉黑、不举报、不关注、不点赞。
- 不调用平台私有接口、不导出 Cookie、不绕过验证码。

它**不能**保证：

- 账号绝对不被平台判定异常。自动点击/自动滚动仍然可能违反平台用户协议。
- 100% 识别所有恶意私信。模型和规则都会漏判/误判。
- 平台改版后仍然可用。DOM 选择器需要维护。

因此建议顺序：

1. 先只开“预览标注 + 遮挡”，完全不自动点击，观察 3–7 天。
2. 没有异常，再开“自动展开未读私信”，并把每日上限设低（比如 20 条）。
3. 最后才考虑“自动滚动收集评论”。
4. **永远不要**加自动回复、自动拉黑、自动举报。误判代价不可逆。

如果你不能接受任何封号风险，就不要开启自动点击；只用预览标注和手动收集。

## 1. 准备清单

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10/11 64 位 |
| 浏览器 | Chrome 或 Edge，能正常登录 B 站/小红书 |
| 内存 | 建议 16 GB；7B 模型最低约 8 GB 可用内存 |
| 硬盘 | 至少 10 GB 空闲（模型约 5 GB） |
| Python | 3.10 或更高 |
| Ollama | 最新版 |
| 账号 | 只处理你**本人**的账号，不要代运营他人账号 |

## 2. 安装 Python

### 2.1 下载

打开：

<https://www.python.org/downloads/windows/>

点 **Download Python 3.x.x**（最新的稳定版即可）。

### 2.2 安装

双击安装包，**务必勾选**：

- [x] Add python.exe to PATH
- [x] Install launcher for all users（可选）

然后点 **Install Now**。

### 2.3 验证

按 `Win + R`，输入 `powershell`，回车。输入：

```powershell
python --version
```

应该看到：

```text
Python 3.12.x
```

如果提示“无法将 python 项识别为 cmdlet”，说明 PATH 没配好。重新安装并勾选 **Add python.exe to PATH**，或者改用：

```powershell
py -3 --version
```

后面的命令如果 `python` 不行，就把 `python` 换成 `py -3`。

## 3. 安装 Ollama 和中文模型

### 3.1 下载 Ollama

打开：

<https://ollama.com/download>

下载 Windows 版，双击安装。安装完成后 Ollama 通常会自动在后台运行，任务栏右下角能看到它的图标。

### 3.2 验证

新开一个 PowerShell 窗口：

```powershell
ollama --version
```

应该显示版本号。

如果提示找不到命令，关掉 PowerShell 再开一次；还不行就重启电脑。

### 3.3 拉取模型

```powershell
ollama pull qwen2.5:7b-instruct
```

- 模型大约 4.7 GB，下载时间取决于网速。
- 看到 `success` 即完成。

### 3.4 测试模型

```powershell
ollama run qwen2.5:7b-instruct "用一句中文回答：你准备好了吗？"
```

能正常回答即可。输入 `/bye` 退出。

### 3.5 低配电脑怎么办

如果内存/显存不够，可以换：

```powershell
ollama pull qwen2.5:1.5b-instruct
```

然后打开项目根目录的 `.env`（没有就从 `.env.example` 复制一份），把：

```text
CG_OLLAMA_MODEL=qwen2.5:7b-instruct
```

改成：

```text
CG_OLLAMA_MODEL=qwen2.5:1.5b-instruct
```

1.5B 更快，但误判会更多。**不建议**用 1.5B 做“违法/恶意”的最终判断，最好只让它做初筛。

## 4. 放置项目

### 4.1 推荐路径

把整个 `creator-guard` 文件夹放到：

```text
C:\CreatorGuard
```

不要放在：
- 微信/QQ 的临时文件夹
- 带大量中文和空格的深层目录（不是绝对不行，但排错麻烦）
- OneDrive 同步目录（数据库文件可能被同步锁住）

放好后，目录里应该有：

```text
C:\CreatorGuard\start.bat
C:\CreatorGuard\server\
C:\CreatorGuard\extension\
```

### 4.2 如果你拿到的是压缩包

右键 → **全部解压缩**，不要直接在压缩包里双击 `start.bat`。

## 5. 启动本地服务

### 5.1 第一次启动

双击：

```text
C:\CreatorGuard\start.bat
```

> 如果还没装 Ollama、只想先看界面和规则标注，改双击 `start-mock.bat`。它不调用大模型，只跑规则层。

会看到一个黑色命令行窗口，依次发生：

1. 创建 `.venv` 虚拟环境。
2. 安装 FastAPI、Uvicorn、httpx 等依赖。
3. 启动服务。
4. 自动打开浏览器 `http://127.0.0.1:8765`。

第一次安装依赖可能需要 1–3 分钟。看到类似：

```text
Uvicorn running on http://127.0.0.1:8765 (Press CTRL+C to quit)
```

就是成功了。

> **这个黑窗口不要关。** 关掉它，扩展就分析不了。可以最小化。

### 5.2 验证服务

浏览器打开：

<http://127.0.0.1:8765/api/health>

应该看到一段 JSON，其中：

```json
{
  "ok": true,
  "llm": {
    "backend": "ollama",
    "reachable": true,
    "model_present": true,
    "model": "qwen2.5:7b-instruct"
  }
}
```

- `reachable: false`：Ollama 没启动。
- `model_present: false`：模型没拉取，或 `.env` 里的模型名和实际不一致。

### 5.3 如果 8765 端口被占用

报错里会出现 `address already in use`。先关掉可能占用端口的程序，或者改用其他端口：

1. 打开 `.env`，加一行：

```text
CG_PORT=8766
```

2. 但 `start.bat` 里也写死了 `--port 8765`，需要同时改：

```bat
".venv\Scripts\python.exe" -m uvicorn server.app:app --host 127.0.0.1 --port 8766
```

3. 扩展弹窗里的“本地服务地址”也要改成 `http://127.0.0.1:8766`。

### 5.4 如果双击 `start.bat` 被“智能应用控制”阻止

先看弹窗长什么样：

| 弹窗 | 是什么 | 怎么做 |
|---|---|---|
| 有 **更多信息 → 仍要运行** | Windows SmartScreen | 点“更多信息”，再点“仍要运行” |
| 只有“确定”，没有“仍要运行” | Windows 智能应用控制（Smart App Control） | 不要反复双击，按下面 A/B/C 处理 |

智能应用控制比 SmartScreen 严格，**没有“这次放过”的按钮**。它不是杀毒软件报毒，而是认为这个 `.bat` 的来源/签名不够可信。不要为了它直接关掉整个安全功能。

#### 方案 A：先解除文件锁定，再试一次

如果是网盘/浏览器下载的压缩包，解压前先右键压缩包 → **属性** → 勾选 **解除锁定 / Unblock** → 确定，再解压。

已经解压了，就在 PowerShell 里执行：

```powershell
cd C:\CreatorGuard
Get-ChildItem -Recurse -File | Unblock-File
```

然后再双击 `start.bat`。

#### 方案 B：从终端运行，不双击

打开 PowerShell：

```powershell
cd C:\CreatorGuard
cmd /c start.bat
```

很多情况下，智能应用控制拦的是“从资源管理器双击”这个动作；由 `cmd.exe` 读取批处理可以正常跑。

#### 方案 C：用 `start.py`，完全绕开 `.bat`

项目根目录已经放了 `start.py`，它做和 `start.bat` 一样的事：

1. 检查 Python 版本。
2. 创建 `.venv`。
3. 安装依赖。
4. 启动 `http://127.0.0.1:8765`。
5. 自动打开浏览器。

在 PowerShell 里：

```powershell
cd C:\CreatorGuard
py -3 start.py
```

如果 `py` 不可用：

```powershell
python start.py
```

不想自动开浏览器：

```powershell
python start.py --no-browser
```

停止服务：在这个窗口按 `Ctrl + C`。

#### 如果连 `python start.py` 也被阻止

说明智能应用控制连 Python 解释器都不信任。按顺序试：

1. 用 **Microsoft Store** 安装 Python（商店应用通常有微软签名）：
   <https://apps.microsoft.com/detail/9ncvdn91xzqp>
2. 安装后在 PowerShell 里：

```powershell
python --version
cd C:\CreatorGuard
python start.py
```

3. 还不行，就把 Python 换成商店版后重开一个 PowerShell 窗口再试。
4. **不建议**为了这个项目关闭“智能应用控制”。关闭后通常要重置/重装 Windows 才能重新打开；如果你确定要关，路径是：
   `Windows 安全中心 → 应用和浏览器控制 → 智能应用控制 → 关闭`
   风险自负。

#### 不要做的事

- 不要连续双击几十次，系统会一直拦。
- 不要从不可信网站下载“破解版 Python”或“免安装 Python”。
- 不要把 `start.bat` 改成 `.exe` 再双击；未签名的 `.exe` 更容易被拦。
- 不要为了绕过安全提示去关 Defender 的实时保护。

## 6. 加载浏览器扩展

### 6.1 Chrome

1. 地址栏输入：

```text
chrome://extensions
```

2. 右上角打开 **开发者模式**。
3. 点 **加载已解压的扩展程序**。
4. 选择：

```text
C:\CreatorGuard\extension
```

注意：选 `extension` 文件夹，不是 `C:\CreatorGuard`。

5. 加载成功后，列表里出现 **Creator Guard · 私信评论守护**。
6. 点浏览器工具栏的拼图图标，把 Creator Guard **固定**出来。

### 6.2 Edge

1. 地址栏输入：

```text
edge://extensions
```

2. 打开 **开发人员模式**。
3. 点 **加载解压缩的扩展**。
4. 选择 `C:\CreatorGuard\extension`。

### 6.3 更新扩展代码后

每次改了 `extension` 里的文件，都要：

1. 打开 `chrome://extensions`。
2. 找到 Creator Guard。
3. 点右下角的 **刷新** 图标。
4. 回到 B 站/小红书页面，按 `F5` 刷新。

只刷新网页、不刷新扩展，改的 JS 不会生效。

## 7. 配置扩展

点工具栏的 Creator Guard 图标。

### 7.1 测试连接

- 本地服务地址：`http://127.0.0.1:8765`
- 点 **测试连接**。

应该显示：

```text
本地服务 + 模型已就绪
模型：qwen2.5:7b-instruct
```

如果显示：

- `连不上本地服务`：`start.bat` 窗口是不是关了？地址是不是写错？
- `Ollama 已启动，但模型未就绪`：运行 `ollama pull qwen2.5:7b-instruct`。
- `本地服务已启动，但 Ollama 没连上`：Ollama 没启动，重新打开 Ollama。

### 7.2 第一次的推荐设置

| 设置 | 推荐值 | 原因 |
|---|---|---|
| 自动展开未读私信 | **关** | 先零点击观察，风险最低 |
| 自动滚动收集评论 | **关** | 先用当前屏手动收集 |
| 遮住恶意私信预览 | **开** | 这是核心保护 |
| 高风险私信不展开 | **开** | 预览命中恶意/违法时直接跳过 |
| 单次最多私信 | 20 | 即使开了自动展开，也不要一次跑太多 |
| 每日最多私信 | 60 | 建议先设 20 |
| 评论最多滚动屏数 | 30 | 不要一次翻几百屏 |
| 活跃开始/结束小时 | 9 / 23 | 半夜自动操作更像机器人 |

### 7.3 设置保存

改完会自动保存，底部显示“已保存”。如果改地址，会重新测试连接。

## 8. B 站私信实操

### 8.1 打开页面

打开：

<https://message.bilibili.com/>

等 3–5 秒。右上角应该出现一个深色标题的 **私信守护 · 本地分析** 面板。

### 8.2 你应该看到什么

- 会话列表里，命中规则的私信右侧出现标签：
  - 红色：`恶意私信，建议拉黑`
  - 深红：`涉嫌违法行为，建议截图留存`
  - 蓝色：`寻求合作，请尽快处理`
  - 绿色：`有效建议`
  - 橙色：`广告/引流，建议忽略`
- 恶意/违法的会话，预览文字被盖住，显示“预览已隐藏”。
- 如果页面打开时，右边聊天区正好是一个已被标记的恶意/违法会话，聊天区也会被白色遮罩盖住；想读原文可以点遮罩里的 **仍要查看原文**。
- 面板显示“今日 0/60 · 本页 0”。

### 8.3 只做预览标注（推荐先这样）

保持“自动展开未读私信”关闭。

- 页面加载后会自动请求 `/api/dm/preview`，对当前可见会话做规则快筛。
- 不会点开任何私信，不会把未读变已读。
- 点面板上的 **刷新标注** 可以重新扫一遍。
- 已经分析过的会话，会从 SQLite 缓存读取完整标签。

### 8.4 打开自动展开（确认风险后再做）

1. 点扩展图标。
2. 打开 **自动展开未读私信**。
3. 弹窗会再次警告；确认后才会保存。
4. 回到私信页面，按 `F5` 刷新。
5. 面板会显示“正在读取「xxx」…”。

行为：

- 每次只点一个会话。
- 点开后，聊天区会被一个白色遮罩盖住，显示“Agent 正在读取…”，博主不会看到辱骂文字。
- 读完按字数等待 1.4–7.4 秒，再等 3.2–7.8 秒，才点下一个。
- 每 10 条强制休息 2.5–4 分钟。
- 每日达到上限会停。
- 高风险私信如果预览已经命中，会直接跳过，不点开。

### 8.5 重要：未读会变已读

平台没有“只读全文但保持未读”的公开能力。点开就会变已读。这是这个方案无法避免的代价。

如果你需要保留未读红点，就不要开自动展开，只用预览标注。

### 8.6 如果完全没有标签

说明选择器没匹配上当前页面。按下面步骤校准。

#### 第一步：找到会话项的真实 class

1. 在私信页面按 `F12` 打开开发者工具。
2. 点左上角的“选择元素”箭头。
3. 鼠标点一个会话条目。
4. 在 Elements 面板里看它的 `class`，例如：

```html
<div class="conversation-item conversation-item--active">
```

5. 再点它里面的预览文字，看 class，例如：

```html
<div class="last-message">傻逼...</div>
```

#### 第二步：改选择器文件

用记事本或 VS Code 打开：

```text
C:\CreatorGuard\extension\content\selectors.js
```

找到 `bilibili.dm.item` 数组，把新 class 加到**最前面**：

```js
item: [
  ".conversation-item",              // ← 新加的放最前
  '[class*="conversation-item"]',
  '[class*="session-item"]',
  // ...
],
```

找到 `preview` 数组，把预览文字的 class 加到最前面：

```js
preview: [
  ".last-message",                   // ← 新加的放最前
  '[class*="last-message"]',
  // ...
],
```

如果有未读红点，把它的 class 加到 `unread`：

```js
unread: [
  ".unread-badge",                   // ← 新加的放最前
  '[class*="unread"]',
  // ...
],
```

#### 第三步：刷新扩展和页面

1. `chrome://extensions` → Creator Guard → 刷新图标。
2. 回私信页面 → `F5`。

#### 第四步：还不行就看控制台

1. `F12` → Console。
2. 刷新页面。
3. 看有没有 `[CreatorGuard]` 开头的报错。
4. 把报错和页面截图发给我，我帮你改选择器。

> 平台改版是常态。选择器失效不是程序坏了，是页面结构变了。`selectors.js` 就是为此单独拆出来的。

## 9. B 站评论实操

### 9.1 打开视频

打开任意有评论的 B 站视频，例如：

```text
https://www.bilibili.com/video/BVxxxxxxxxx
```

等 3–5 秒。右下角出现 **评论守护 · 本地分析** 面板。

### 9.2 手动收集当前屏

1. 点 **收集当前屏**。
2. 面板显示“正在分析 N 条评论…”。
3. 完成后点 **立即更新统计**。
4. 面板顶部出现：
   - `42% 的评论集中在「感动/共鸣」（基于 128 条评论）`
   - `有效建议 · 优先看这里`
   - 建议 1/2/3
   - 评论构成条形图
   - 分类 chips：有效建议 23、正向夸奖 54、恶意攻击 2…

### 9.3 自动滚动收集

1. 扩展弹窗 → 打开 **自动滚动收集评论**。
2. 回到视频页刷新。
3. 面板会按 1.5–2.9 秒一屏的速度往下翻，最多 30 屏。
4. 连续 3 屏没有新评论就停。
5. 收集完自动更新统计。

### 9.4 5 天统计是什么意思

- 第一次打开某个视频的评论区：没有快照 → 立即计算一次，存为快照。
- 5 天内再打开：直接显示这个快照，不会重复调用模型。
- 5 天后：后台或下次打开时重新计算。
- **5 天是刷新频率，不是只统计最近 5 天。** 快照会包含这个视频下已经收集到的全部评论；否则旧评论会被悄悄从分母里删掉，占比就不准了。
- 面板会显示：

```text
统计时间 11-07 19:30 · 每 5 天更新一次
有 12 条新评论，将在下一次 5 天统计中计入。
```

- 想立刻看最新数据，点 **立即更新统计**（会强制刷新，适合调试）。

### 9.5 为什么占比不是模型编的

模型只给每条评论打标签；占比是后端算的：

```python
pct = round(count / total * 100)
```

所以 `42%` 是真实的 `54 / 128`，不是模型随口说的。

### 9.6 如果评论区识别不到

B 站新版评论区不是普通 DOM，而是 `<bili-comments>` Web Components，评论在 **open Shadow DOM** 里。普通 `document.querySelectorAll('.reply-item')` 是看不到的。

当前版本已经做了 shadow root 穿透，优先找：

```text
bili-comment-renderer
bili-comment-reply-renderer
bili-rich-text 里的 #contents
```

如果仍然识别不到：

1. 确认网页版 B 站已登录，评论区能看到具体评论，不只是“评论 24 万”这个标题。
2. 滚到评论区，等 2–3 秒。

## 12. 安全节奏参数

### 12.1 扩展弹窗里能改的

- 单次最多私信
- 每日最多私信
- 评论最多滚动屏数
- 活跃开始/结束小时

### 12.2 代码里能改的

打开：

```text
C:\CreatorGuard\extension\content\dm-core.js
```

找到：

```js
CG.humanReadingDelay = (textLength) => {
  const base = 1400 + Math.min(textLength * 38, 6000);
  return Math.round(base * (0.8 + Math.random() * 0.5));
};

CG.betweenItemsDelay = () => CG.rand(3200, 7800);
```

- `1400`：基础停留毫秒。
- `38`：每个字增加的毫秒。
- `6000`：最长增加 6 秒。
- `0.8 / 0.5`：随机抖动范围。
- `3200, 7800`：两条之间的间隔。

想更保守：

```js
const base = 2200 + Math.min(textLength * 55, 8000);
return Math.round(base * (1.0 + Math.random() * 0.8));
```

```js
CG.betweenItemsDelay = () => CG.rand(6000, 14000);
```

改完刷新扩展 + 页面。

### 12.3 强制休息

在 `dm-core.js` 里：

```js
if (processedThisRun % 10 === 0) {
  await CG.sleep(CG.rand(150000, 240000));
}
```

- 每 10 条休息 150–240 秒。
- 可以改成 5 条，或更长。

### 12.4 不要做的事

- 不要把间隔改成 0。
- 不要同时开多个标签页跑。
- 不要用代理轮换 IP。
- 不要改 `navigator.webdriver`、User-Agent 伪装。
- 不要绕过验证码/风控页。
- 不要自动回复/拉黑/举报。

## 14. 常见问题

### Q1：扩展弹窗显示“连不上本地服务”

按顺序检查：

1. `start.bat` 黑窗口还在吗？
2. 浏览器打开 <http://127.0.0.1:8765/api/health> 能访问吗？
3. 扩展里的地址是不是 `http://127.0.0.1:8765`，有没有多写空格/斜杠？
4. 端口是不是被占用？看 `start.bat` 报错。
5. 有没有开 VPN/代理导致 localhost 被代理？把 `127.0.0.1` 加入代理例外。

### Q2：显示“Ollama 已启动，但模型未就绪”

```powershell
ollama list
```

看有没有 `qwen2.5:7b-instruct`。没有就：

```powershell
ollama pull qwen2.5:7b-instruct
```

如果你在 `.env` 里改了模型名，要和 `ollama list` 里的名字完全一致。

### Q3：模型很慢/超时

- 7B 在 CPU 上会比较慢，第一次加载尤其慢。
- 把 `CG_OLLAMA_TIMEOUT` 改大，比如 `180`。
- 换 1.5B 只做初筛。
- 评论区一次只发 8 条，已经做了批处理；不要一次几百条。

### Q4：面板不出现

1. 扩展加载了吗？`chrome://extensions` 里有没有报错？
2. 当前 URL 匹配吗？
   - B 站私信：`https://message.bilibili.com/*`
   - B 站视频：`https://www.bilibili.com/video/*`
   - 小红书私信：`https://www.xiaohongshu.com/im*`
   - 小红书笔记：`https://www.xiaohongshu.com/explore/*`
3. 按 `F5` 刷新页面。
4. `F12` → Console 看 `[CreatorGuard]` 报错。

### Q5：有面板，但没有标签

选择器没匹配。按 8.6 校准 `selectors.js`。

### Q6：标签有，但遮罩没盖住文字

说明预览元素找错了。打开 `selectors.js`，把真正的预览文字 class 加到 `preview` 数组最前面。CSS 在：

```text
C:\CreatorGuard\extension\styles\overlay.css
```

### Q7：点开私信后，聊天区遮罩位置不对

`dm-core.js` 里的 `findDetailPanel()` 找错了面板。把聊天区容器的真实 class 加到 `selectors.js` 的 `detail` 数组最前面：

```js
detail: [
  ".chat-panel",                  // ← 新 class 放最前
  '[class*="chat-panel"]',
  // ...
],
```

### Q8：评论区自动滚动不动

- 小红书可能是弹层容器，先手动往下滚一点。
- 把评论容器的 class 加到 `selectors.js` 的 `comments.container`。
- 如果页面本身不滚动，而是内部 `div` 滚动，代码会找 `scrollHeight > clientHeight` 的容器。

### Q9：模型返回的 JSON 解析失败

- 7B 一般没问题；1.5B 容易输出不稳定。
- 看 `start.bat` 窗口的 `WARNING` 日志。
- 代码会自动退回规则层，不会让页面崩。
- 想更稳：换 7B，或把 `CG_OLLAMA_TIMEOUT` 调大。

### Q10：会不会被平台封号

不能保证不被封。自动点击/滚动本身就可能违反平台用户协议。这个项目做了：

- 单线程、低频、随机间隔
- 每日上限、单次上限
- 活跃时段
- 每 10 条强制休息
- 不回复、不拉黑、不举报
- 不绕过验证码

但**不能消除风险**。最稳的是只开预览标注，不自动点击。

### Q11：能不能自动回复/自动拉黑

本项目故意不做。原因：

- 误判代价不可逆。
- 自动回复/拉黑/举报更容易被判定异常。
- 平台规则风险更高。

面板只给建议，最终由人操作。

### Q12：能不能分析图片/语音私信

当前只读文字 DOM。图片文字需要 OCR（PaddleOCR），语音需要 ASR；默认没开，因为会增加复杂度和隐私风险。后续可以加。

## 15. 平台改版后的修复流程

平台改版后，通常只坏在选择器，不会坏在服务端。修复顺序：

1. 打开出问题的页面，`F12`。
2. 用元素选择器点中一个会话/评论。
3. 记下最外层 item 的 class、正文的 class、未读红点的 class。
4. 打开 `extension/content/selectors.js`，把新 class 加到对应数组最前面。
5. `chrome://extensions` → 刷新扩展。
6. 回页面 `F5`。
7. 如果还不行，看 Console 的 `[CreatorGuard]` 报错。
8. 把报错、页面截图、DOM 结构发给我，我帮你改。
